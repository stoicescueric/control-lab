# Take-Back-Half

<Difficulty level="Medium" />

<Abstract>
Bang-bang recovers a flywheel's speed fast but chatters and never truly settles. <strong>Take-back-half</strong>
(TBH) is a tiny modification — integrate the error like an integrator, and when the error changes sign, give
back half the accumulated drive — that converges to a steady, ripple-free hold while keeping bang-bang's
fast recovery after a shot. One gain, no derivative, no windup.
</Abstract>

<Admonition type="note" title="Prerequisite">

This page extends [**Bang-Bang Control**](../control-theory/bang-bang.mdx). It assumes you know why a
high-inertia flywheel suits an on/off law and why plain bang-bang chatters in a limit cycle around the
setpoint.

</Admonition>

<Theory title="Settle without giving up recovery">

Take-back-half keeps an accumulating drive like an integrator, but adds one trick. Each loop, integrate the
error into the drive. When the error **crosses zero**: the moment you pass the setpoint — you have
integrated too far, so "take back half": set the drive to the average of its current value and its value
at the *previous* crossing. Successive crossings bracket the true holding drive and converge onto it.

$$
\begin{gathered}
\text{drive} \mathrel{+}= g\,e\,\Delta t \\[3pt]
\text{on a sign change of } e:\quad
\text{drive} \leftarrow \tfrac12\big(\text{drive} + \text{drive}_\text{last-cross}\big)
\end{gathered}
$$

<EquationLegend
  items={[
    {symbol: 'drive', meaning: 'the running output, from 0 to 1. It is pure integrator: nothing resets it except the take-back rule'},
    {symbol: 'g', meaning: 'the single tuning gain. TBH exists because one gain is easier to get right than three', unit: 'power per (error \u00b7 s)'},
    {symbol: 'drive_last-cross', meaning: 'the value drive held the PREVIOUS time the error changed sign. Averaging against it is what brackets the true holding value'},
    {symbol: 'a sign change of e', meaning: 'the moment the mechanism crosses its target. Each crossing shrinks the remaining oscillation by at least half, which is why successive crossings converge'},
  ]}
/>

The result (green below) recovers nearly as fast as bang-bang on the first approach, then quickly stops
oscillating and holds the speed flat. One gain $g$, no derivative, no windup to manage. Run the demo:
bang-bang chatters around the line forever; TBH locks on.

<BangBang />

<Callout type="idea" title="Why take back half?">
At each zero crossing the true steady drive lies somewhere between the current over-driven value and the
last under-driven one. Halving splits the difference — a bisection search on the holding voltage that
converges geometrically. It is the cheapest possible way to find the steady command without a model.
</Callout>

</Theory>

<Deploy title="Take-back-half on the Control Hub">

<JavaCode league="FTC" label="Takeback-half velocity controller">{`private double drive;         // the current output
private double driveAtZero;   // the output at the last error sign change
private Double lastError;     // null until the first update

double update(double measured, double target, double dt) {
    double error = target - measured;
    drive = clamp(drive + GAIN * error * Math.max(0, dt), 0, 1);

    if (error != 0) {
        if (lastError != null && Math.signum(error) != Math.signum(lastError)) {
            drive = (drive + driveAtZero) / 2;
            driveAtZero = drive;
        }
        lastError = error;
    }
    return drive;
}
`}</JavaCode>

A zero error is skipped so it cannot fake a second crossing.

<Exercise title="Why halving converges">

TBH is a pure integrator with one trick: whenever the error changes sign, it jumps the output halfway
back toward whatever it was at the *previous* crossing. Sketch a flywheel overshooting, crossing,
undershooting, crossing again, and mark `drive` at each crossing.

<Solution>

Each crossing brackets the true holding voltage — one crossing happens with the output too high, the
next with it too low. Halving between consecutive crossings is a bisection search on that bracket, so
the oscillation shrinks by at least half at every crossing — often by much more, since the plant is also
damping it between crossings — and the output converges geometrically on the command that holds the
target speed. No model, no second gain.

</Solution>

</Exercise>

<Exercise title="Why a flywheel, and why [0, 1]">

Work out why this suits a flywheel where a PID struggles: a flywheel has huge inertia and asymmetric
authority, since the motor can push hard but can only coast down. What does an integrator with
anti-windup have to be told to handle that, and how many gains did you tune to get there? Then work out
why `drive` is clamped to $[0, 1]$ rather than $[-1, 1]$.

<Solution>

A PID needs `kP`, `kI`, `kD`, an I-zone, and an anti-windup rule to survive the asymmetry — five
decisions, several of which interact. TBH needs `GAIN`. The clamp is $[0, 1]$ because a negative
command means driving the flywheel backwards, which no shooter wants: the only way down is to stop
pushing and let drag do it. Allowing negatives would let a single overshoot brake the wheel and cost
far more recovery time than coasting.

Look up "take back half controller," originally from VEX flywheel control, and compare its step
response to a tuned PI on the same mechanism.

</Solution>

</Exercise>

Seed `driveAtZero` with a [feedforward](../control-theory/feedforward.mdx) estimate and TBH converges in
a single oscillation instead of several — the two techniques compose nicely. Mind the units when you do:
$k_V$ is defined in **volts** per unit speed, while `drive` here is normalized power in $[0, 1]$, so the
seed is $k_V \cdot v_\text{target} / V_\text{bat}$. Skip that division and the seed lands far outside the
variable's range — for a flywheel with $k_V = 0.02$ at 300 rad/s it evaluates to 6.0, six times full
power, and TBH starts pinned at the ceiling instead of near the answer.

</Deploy>

<Admonition type="tip" title="When to reach for which">

Use **[bang-bang](../control-theory/bang-bang.mdx)** when recovery speed is everything and the plant is
high-inertia (a shooter you re-spin between shots). Use **take-back-half** when you also need a steady,
repeatable speed (consistent shot distance). Use **[PID](../control-theory/pid.mdx) + feedforward** when
you need both tight holding *and* controlled acceleration, or the mechanism isn't a flywheel.

</Admonition>
