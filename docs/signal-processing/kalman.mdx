# Kalman Filter

<Difficulty level="Hard" />

<Abstract>
A Kalman filter predicts where something should be from a model, then corrects that prediction with a
measurement. How far it corrects depends on how uncertain the prediction is compared with the sensor,
and it keeps track of its own uncertainty as it goes. This lesson works a one-number filter by hand,
then shows the matrix version and what changes in an Extended Kalman Filter.
</Abstract>

<Admonition type="note" title="Before you start">

You don't need a probability course. [Signals & Noise](./signals.mdx) covers the average and the
standard deviation, which is enough, and the [Complementary Filter](./complementary.mdx) introduces the
predict-then-correct idea with a fixed blend. The matrix section later in the lesson is optional; get the
one-number filter working first. If you want more background on variance and the bell curve,
[kalmanfilter.net](https://kalmanfilter.net/background.html) has a good introduction.

</Admonition>

The complementary filter blends two sources with a weight you pick once. A Kalman filter works out the
weight itself, every loop, from how uncertain each source is right now. Under the right conditions
(a linear model, and noise that's random, bell-shaped, and not correlated from one loop to the next),
that weight is the best possible one.

The last condition is the one real sensors break most often. A camera on a bent mount, or a tag
measured in the wrong place, is off by the same amount every time. That's a bias, not random noise, and
a Kalman filter will settle confidently on the biased answer. Calibrate the sensor first.

<Problem>

## How much should you trust the camera?

Say your robot tracks its position with odometry, which is smooth but drifts, and sometimes sees an
AprilTag, which gives a noisy but absolute position. Right after a good tag sighting, odometry is very
trustworthy. After ten seconds without seeing a tag, it's much less so. A fixed blend weight can't tell
those situations apart, and it can't tell you how confident the result is.

</Problem>

the green curve is the combined estimate. A wide curve means that source is uncertain, and a narrow one
means it's confident. Change the widths and watch the estimate move toward whichever curve is narrower.

## A one-number Kalman filter

Track one number, say the robot's $x$ position. The filter keeps two things: the estimate `xHat`, and
its variance `P`, which is how uncertain the estimate is (the standard deviation squared). Each loop it
does two steps.

**Predict.** Move the estimate by the measured motion `delta`, and add `Q` to `P`, because every
prediction adds some uncertainty.

**Correct**, whenever a measurement `z` arrives. Work out a gain `K` between 0 and 1 from how uncertain
the prediction is (`P`) compared with the sensor (`R`). Move the estimate that fraction of the way
toward the measurement, and shrink `P`, since you now know more.

<JavaCode league="FTC" label="Persistent scalar predict/correct loop">{`private double xHat;   // the estimate; start at your best guess
private double P;      // its variance; start LARGE if the guess is poor
private double Q;      // process noise: how far truth drifts per loop
private double R;      // measurement noise: how much the sensor lies

// Every loop, from a measured displacement.
void predict(double delta) {
    xHat += delta;
    P += Q;
}

// Only when a validated measurement exists.
void correct(double z) {
    double K = P / (P + R);      // the Kalman gain
    xHat += K * (z - xHat);      // (z - xHat) is the innovation
    P = (1 - K) * P;
}`}</JavaCode>

Run it by hand. Start at $\hat x = 0$ with $P = 4$. Each loop the robot moves `delta = 1`, with `Q = 1`
and `R = 4`, and the measurements are 1.2, 2.1, and 2.9.

Loop 1: predict $\hat x = 1$ and $P = 4 + 1 = 5$. The gain is $5 / (5 + 4) = 0.556$. The measurement is
0.2 above the prediction, so move $0.556 \times 0.2 = 0.111$ toward it: $\hat x = 1.111$. Then
$P = (1 - 0.556) \times 5 = 2.222$. Carrying on:

| Loop | prediction $\hat x^-$ | gain $K$ | corrected $\hat x$ | corrected $P$ |
|---:|---:|---:|---:|---:|
| 1 | 1.000 | 0.556 | 1.111 | 2.222 |
| 2 | 2.111 | 0.446 | 2.106 | 1.785 |
| 3 | 3.106 | 0.410 | 3.022 | 1.642 |

The gain starts high, because the starting guess was poor, and settles lower as the filter becomes more
confident. If you can trace a loop like this and explain why a bigger `P` gives a bigger gain, you
understand the Kalman filter. Everything else is the same idea with more numbers.

<Exercise title="The two extremes of the gain">

What does $\hat x$ become when $P$ is much bigger than $R$? When $R$ is much bigger than $P$? Now picture a
robot that runs `predict` at 50 Hz from odometry but only runs `correct` when an AprilTag is in view.
What happens to $P$ during a long stretch without a tag, and to the gain when a tag finally shows up?

<Solution>

With $P \gg R$ the gain approaches 1 and $\hat x \to z$: the filter drops its own estimate and believes the
sensor. With $R \gg P$ the gain approaches 0 and the measurement barely matters. Between tags, `predict`
adds $Q$ every loop, so $P$ keeps growing. The longer the robot goes without a tag, the bigger $P$ is when
one appears, and the harder the estimate snaps to it. That's what you want, and it's also why one
tag seen from a bad angle can yank the pose.

</Solution>

</Exercise>

<Exercise title="Where the low-pass α came from">

The low-pass filter and this one both compute `estimate + gain * (measurement - estimate)`. The only
difference is where the gain comes from. With $Q$ and $R$ held constant, what does $K$ settle to after many
loops? (Look for the value of the predicted $P$ that stays the same from one loop to the next.) Then try
$Q = 0$.

<Solution>

Call the steady predicted variance $p$. Staying the same means $p = \frac{Rp}{p+R} + Q$, which
rearranges to $p^2 - Qp - QR = 0$, so

$$
p = \frac{Q + \sqrt{Q^2 + 4QR}}{2}, \qquad K_\infty = \frac{p}{p + R}.
$$

With $Q = 1$ and $R = 4$ that's $p = 2.562$ and $K_\infty = 0.390$, which is where the table above was
heading (0.556, 0.446, 0.410). Once it settles, this Kalman filter *is* a low-pass filter. Its $\alpha$
just came from your noise numbers instead of a guess.

With $Q = 0$, nothing ever makes $P$ grow again, so $1/P_k = 1/P_0 + k/R$ and $K$ keeps shrinking toward
zero. Each new measurement counts for less and less. That's right for something that truly never
changes, but it makes the filter slower and slower to notice anything the model didn't expect. It never
quite stops updating, though; the gain only approaches zero.

</Solution>

</Exercise>

Set $R$ from the standard deviation you measured in [Signals & Noise](./signals.mdx): it's that number
squared. $Q$ is the harder one to pick. Start from how much drift you actually see between corrections
and adjust from there.

<Theory>

## More than one number (optional)

A robot's state is usually more than one number, for example position and velocity together. The
matrix version tracks all of them at once, along with how their uncertainties are related. The steps
are the same.

**Predict** the state with a model, and grow the uncertainty:

$$
\hat{x}^- = A\hat{x} + Bu, \qquad P^- = A P A^\top + Q
$$

<EquationLegend
  items={[
    {symbol: 'x̂⁻, P⁻', meaning: 'the prediction and its uncertainty, before any measurement. The minus sign always means "before correcting"'},
    {symbol: 'A', meaning: 'how the state moves on its own from one loop to the next'},
    {symbol: 'B, u', meaning: 'how the command u (like a commanded velocity) changes the state'},
    {symbol: 'P', meaning: 'the covariance: the uncertainty of each state and how they relate'},
    {symbol: 'Q', meaning: 'the uncertainty added each loop because the model is never perfect'},
  ]}
/>

$APA^\top$ reshapes the existing uncertainty as the state moves, and $Q$ is added on top. With one state
and $A = 1$, this is just $P + Q$ from the code above.

**Correct** with a measurement $z$:

$$
K = P^- H^\top (H P^- H^\top + R)^{-1}, \qquad
\hat{x} = \hat{x}^- + K\,(z - H\hat{x}^-), \qquad
P = (I - KH)P^-
$$

$H$ turns a state into what the sensor would report, because the sensor often doesn't measure the state
directly. A camera might see position but not velocity, for example. $R$ is the sensor's noise, and $I$ is
the identity matrix. With one state and $H = 1$, the gain is $P^-/(P^- + R)$ again, and the matrix inverse
is ordinary division.

The update reads the same way as before. $z - H\hat{x}^-$ is how surprised the filter is by the
measurement, $K$ decides how much of that surprise to believe, and the new estimate is the prediction
plus that much of the surprise. A noisy sensor (large $R$) gives a small $K$, so the estimate stays smooth.
An uncertain prediction (large $P^-$) gives a large $K$, so the estimate jumps toward the measurement.

In the demo, a target follows a curved path and is only reported as noisy dots. The filter recovers a
smooth track and an uncertainty bubble around it. The sensor slider sets the noise's standard deviation
$\sigma$, and the filter's $R = \sigma^2$ matches it. The other slider sets $q$, how much random
acceleration the filter assumes. For each axis the demo uses
$Q = q\begin{bmatrix}\Delta t^4/4 & \Delta t^3/2 \\\Delta t^3/2 & \Delta t^2\end{bmatrix}$ with
$\Delta t = 0.06$ s. The bubble's radius is twice the estimated position standard deviation, as a
picture of the uncertainty rather than a guaranteed boundary.

<Kalman />

<Callout type="warn" title="Q and R are the tuning">
Set <code>Q</code> very low and the estimate lags on sharp turns, because you've told the filter its
model is nearly perfect. Set it high and it chases every noisy dot. <code>Q</code> is how much you
<strong>distrust</strong> the model, so raising it makes the filter trust the sensor more. Picking
<code>Q</code> and <code>R</code> to match the real process and sensor is most of the work of using a
Kalman filter.
</Callout>

</Theory>

## The Extended Kalman Filter

<Admonition type="note" title="This section uses partial derivatives">

It uses partial derivatives and Jacobian matrices. Khan Academy covers
[partial derivatives](https://www.khanacademy.org/math/multivariable-calculus/multivariable-derivatives/partial-derivatives/v/partial-derivatives-and-graphs)
and [the Jacobian](https://www.khanacademy.org/math/multivariable-calculus/multivariable-derivatives/jacobian/v/the-jacobian-matrix).
You can skip it. The linear filter above is complete on its own.

</Admonition>

A robot's motion on the field involves $\sin\theta$ and $\cos\theta$, because moving forward means
different things at different headings. That makes the model nonlinear, and the linear filter can't use
it directly. An **Extended Kalman Filter** (EKF) handles it by predicting with the real nonlinear
functions:

$$
\hat{\mathbf x}^{-}_k=f(\hat{\mathbf x}_{k-1},\mathbf u_k),
\qquad
\hat{\mathbf z}_k=h(\hat{\mathbf x}^{-}_k).
$$

The estimate follows the real motion. The uncertainty still needs a matrix, so each loop the EKF finds
the best straight-line approximation of $f$ and $h$ around the current estimate. Those are the Jacobians:

$$
F_k=\left.\frac{\partial f}{\partial\mathbf x}\right|_{\hat{\mathbf x}_{k-1}},
\qquad
H_k=\left.\frac{\partial h}{\partial\mathbf x}\right|_{\hat{\mathbf x}^{-}_k}.
$$

Then the familiar equations come back with $F_k$ and $H_k$ in place of $A$ and $H$:

$$
P^-_k=F_kP_{k-1}F_k^\top+Q,
$$

$$
K_k=P^-_kH_k^\top(H_kP^-_kH_k^\top+R)^{-1},
$$

$$
\hat{\mathbf x}_k=\hat{\mathbf x}^{-}_k+K_k(\mathbf z_k-h(\hat{\mathbf x}^{-}_k)).
$$

Kou and Haggenmiller's FTC paper, linked below, uses an EKF on a mecanum robot with this state:

$$
\mathbf x=[x,\ y,\ \theta,\ v_x^{body},\ v_y^{body},\ \omega]^\top.
$$

Velocity is tracked in the robot's frame and rotated into the field frame during prediction, which is
where the nonlinearity comes from. Odometry gives frequent velocity measurements, and landmark
sightings give occasional absolute positions, so the EKF can predict through the gaps and remove drift
when a landmark comes back.

<Callout type="warn" title="An EKF is an approximation">

The Jacobians are only accurate close to the current estimate. Long time steps, a bad starting
estimate, strongly nonlinear motion, biased sensors, or unrealistic $Q$ and $R$ can make the uncertainty
wrong or make the filter diverge. The paper found its approximation got worse with longer update
intervals. Recompute the Jacobians every loop, keep timestamps accurate, wrap angle differences, and
reject bad vision readings before correcting.

</Callout>

| Linear KF | Extended KF |
|---|---|
| $A\mathbf x+B\mathbf u$ | nonlinear $f(\mathbf x,\mathbf u)$ |
| $H\mathbf x$ | nonlinear $h(\mathbf x)$ |
| fixed $A,H$ | Jacobians $F_k,H_k$ at the current estimate |
| optimal under its assumptions | an approximation |

For an FTC robot, use a maintained localization library unless building and testing an EKF is itself the
goal. Read the paper once you can follow the matrix equations above.

<Deploy>

## Using it on the robot

For the one-number filter, create it once when the OpMode starts and keep it for the whole OpMode.
Call `predict(deltaX)` every loop with the latest motion from your pose source, and call `correct(tagX)`
only when a vision reading passes your timestamp, calibration, and geometry checks. Don't create a new
filter inside the loop, or it forgets its estimate and uncertainty every time.

Check your pose source against the [Pose Estimation Contract](../path-following/pose-estimation-contract.mdx)
first: frame, units, update rate, and freshness.

<Callout type="tip" title="More than smoothing">
In the demo, the Kalman estimate's error is usually a fraction of the raw measurement error. It's
combining the model and the measurement, not just averaging, which is why the same idea shows up in
GPS, drones, and robot localization.
</Callout>

Full field localization is nonlinear, so for that, use a maintained library's pose estimate. Use this
lesson's filter for one-dimensional signals you combine yourself.

</Deploy>
