# Differential Equations

<Difficulty level="Medium" />

<Abstract>
Cut power to a flywheel at full speed and it does not stop; it coasts for several seconds, quickly at first and then more and more slowly. Nothing in the code changed, so the behaviour is coming from the mechanism itself.
Differential equations are how you write that down: the speed the wheel has right now is what sets how fast it is losing speed.
</Abstract>

Every differential equation on this page says one thing:

> The current state tells you how the state is about to change.

Flywheel speed sets how much back-EMF opposes the applied voltage, which sets how hard the wheel is
still accelerating. Arm angle sets the gravity torque, which sets how fast the arm is falling back down.

## The same motor command behaves differently under load

Your intake spins quickly in the air. Then it touches a game element and slows down. The code did not
change, but the mechanism did.

That is not a software mystery. The motor is a dynamic system. Voltage, back-EMF, friction, inertia,
and load determine acceleration, and acceleration changes speed.

## Writing a mechanism as a rate

The simplest differential equation says a quantity changes in proportion to the gap between where it is
and where it wants to settle:

$$
\frac{dx}{dt} = k(x_\infty - x)
$$

<EquationLegend
  items={[
    {symbol: 'x_\u221e', meaning: 'the value x eventually settles at, if you wait long enough. The infinity subscript means "at the end", not an infinitely large number'},
    {symbol: 'k', meaning: 'how quickly it closes the gap. Here k is a rate constant, not the loop index used elsewhere', unit: '1/s'},
    {symbol: '(x_\u221e \u2212 x)', meaning: 'the remaining gap. Because the rate is proportional to it, big gaps close fast and the approach slows as you arrive'},
  ]}
/>

Here, $x$ is the current state, $x_\infty$ is the value the system approaches if nothing changes, and
$k$ controls how quickly the system moves toward that value.

<DifferentialEquationsIllustration />

If $x$ is flywheel speed, $x_\infty$ is the speed the motor would eventually reach at the current
voltage, and $k$ controls how quickly it approaches.

A more physical motor model writes angular acceleration as the result of torque minus load:

$$
J\frac{d\omega}{dt} = \tau_\text{motor} - \tau_\text{load}
$$

<EquationLegend
  items={[
    {symbol: 'J', meaning: 'rotational INERTIA: how hard the mechanism is to spin up. The rotational counterpart of mass', unit: 'kg\u00b7m\u00b2'},
    {symbol: 'd\u03c9/dt', meaning: 'angular acceleration: how fast the spin rate is changing', unit: 'rad/s\u00b2'},
    {symbol: '\u03c4_motor', meaning: 'the twisting force the motor produces', unit: 'N\u00b7m'},
    {symbol: '\u03c4_load', meaning: 'the opposing torque from the mechanism, gravity, or a game element. Only the DIFFERENCE accelerates anything'},
  ]}
/>

Here, $J$ is rotational inertia, $\omega$ is angular velocity, $\tau_\text{motor}$ is the torque
produced by the motor, and $\tau_\text{load}$ is the opposing torque from the mechanism or game
element. The motor torque depends on current, and current depends on voltage minus back-EMF:

$$
\tau_\text{motor} = k_t I,
\qquad
I = \frac{V - k_e\omega}{R}
$$

Here, $k_t$ is the motor torque constant, $I$ is current, $V$ is applied voltage, $k_e$ is the back-EMF
constant, and $R$ is motor winding resistance.

Substitute them:

$$
J\frac{d\omega}{dt}
=
k_t\frac{V - k_e\omega}{R}
- \tau_\text{load}
$$

That equation is the motor lesson in dynamic form.

## Flywheel recovery

A flywheel shooter needs more than a target speed. It needs to recover after a game element steals
energy from the wheel. A differential-equation view tells you that recovery time is set mostly by two
things: the flywheel's inertia, and how much voltage headroom is left above the speed you are holding.

If the wheel is too light, it loses speed quickly. If it is too heavy, it recovers slowly. Most FTC
shooters take the heavier wheel, because a shot that leaves at the wrong speed is a miss while a longer
recovery is only a slower cycle.

<Admonition type="warning" title="Hardware reality: models bend near limits">

The equations above are idealized. Real FTC mechanisms add gearbox friction and voltage sag on top.
The model is still useful because it tells you which physical effect to look for when behavior
changes.

</Admonition>

<Admonition type="tip" title="FTC intuition">

When something "takes time to settle," you are looking at a differential equation. PID tuning changes
the shape of that settling; feedforward changes the destination the system is trying to settle toward.

</Admonition>
