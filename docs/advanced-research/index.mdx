# Elective Case Study: Drag-Aware Launcher

This optional research track follows one model all the way from a desktop trajectory solver to a
competition robot. It is one worked launcher case study, not a universal curriculum capstone.
The engineering question is precise:

> How can a robot generate and execute a projectile trajectory in real time while the projectile loses
> energy to drag, the launcher loses energy to contact, and the chassis is still moving?

## Readiness

Start this elective after you can use differential equations, measured-loop
[discretization](../software-architecture/discretization.mdx),
[feedforward and PID](../control-theory/feedforward.mdx), interpolation, and
[state feedback](../state-space-control/state-feedback.mdx). You do not need to derive Lambert W to use
the first three on-robot ideas; the lesson marks where that research extension begins.

The implementation pipeline is:

1. Generate candidate trajectories with a quadratic-drag model and RK4 integration.
2. Select feasible launch conditions and turn them into calibrated flywheel, hood, and time-of-flight maps.
3. Control the flywheel so it recovers after each shot.
4. Interpolate sparse calibration data without inventing unsafe overshoot.
5. Compensate inherited chassis velocity with a fixed-point virtual-target solver.

## Lessons

- [**Simulating Physical Reality**](./trajectory-simulation.mdx) - generate trajectories with RK4,
  compare vacuum and drag models, and calibrate wheel-speed-to-exit-velocity transfer.
- [**On-Bot Control & Dynamic Targeting**](./shoot-on-the-move.mdx) - implement flywheel recovery,
  monotone interpolation, and fixed-point shoot-on-the-move aiming.
